## 버그 수정 상세

### B1·B2: Epipe/VPLS SAP description·portDescription 단일 검색어 누락

단일 검색어(`searchTerms.length === 1`) 경로에서 SAP을 `sapId`만으로 검색하고 `description`, `portDescription`을 포함하지 않던 문제 수정.

```
// 수정 전: sapId만 검색
sap.sapId.toLowerCase().includes(query)

// 수정 후: description, portDescription 추가
sap.sapId.toLowerCase().includes(query) ||
normalizeSearchString(sap.description).includes(query) ||
(sap.portDescription && normalizeSearchString(sap.portDescription).includes(query))
```

### B3: Epipe/VPLS Spoke·Mesh SDP description 단일 검색어 누락

SDP 검색에서 `sdpId`, `vcId`만 검색하고 `description` 미포함. Epipe Spoke SDP, VPLS Spoke SDP, VPLS Mesh SDP 모두 수정.

### B3-IES: IES 서비스를 hostname·serviceId·description으로 검색 불가

**근본 원인**: IES가 `return true`로 무조건 통과한 뒤 `.map()` 블록의 `filterIESInterfaces()`가 항상 덮어써서, hostname이나 serviceId로 검색해도 인터페이스 레벨 미매칭 시 결과에서 제외됨.

**수정**: 서비스 레벨 매칭을 먼저 확인하고 매칭 시 전체 인터페이스 표시.

```
// 단일/복수 공통 .map() 블록
const serviceLevelMatch = (
  service.serviceId.toString().includes(query) ||
  normalizeSearchString(service.description).includes(query) ||
  (service.serviceName && ...) ||
  (hostname && normalizeSearchString(hostname).includes(query))
);
if (serviceLevelMatch) return service; // 전체 인터페이스 표시
return filterIESInterfaces(...);       // 미매칭 시 인터페이스 필터
```

### B4: 단일 검색어 Catch-all Unicode 하이픈 정규화 누락

단일 경로 Catch-all에서 `.toLowerCase()`만 사용하여 Unicode 하이픈 변형 문자(U+2010~U+2015 등)가 정규화되지 않던 문제.  
`normalizeSearchString(JSON.stringify(service))`로 교체하여 복수 경로와 일관성 확보.

### B5 (개선): VPRN portDescription 명시적 검색 추가

`L3Interface.portDescription` 필드가 기존에는 Catch-all JSON에서만 우연히 검색되었음. 단일/복수 경로 모두 명시적으로 추가.
